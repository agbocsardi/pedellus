# PWA plan

Each phase ends with something usable on the phone. Gateway work happens in
`durable-nanobot`; app work happens here. The parked native plan is in
[docs/native-ios/](./docs/native-ios/).

## Phase 0 — decisions and checks

- [x] Session model: the app has its own session (carried over)
- [x] Notification body: content-free by default (carried over)
- [x] Client is a PWA over `tailscale serve`; native iOS parked
- [ ] Throwaway page (built: `phase0/`, port 8790) behind `tailscale serve`: install to Home Screen on the
      phone, confirm service worker, Web Push from a `ts.net` origin, badge
- [ ] Confirm the installed app's cookie jar is separate from Safari's
- [x] Pick UI stack: React + Streamdown, `vite-plugin-pwa` (injectManifest), `idb`
- [ ] Read Hermes UI+ and Salchi pairing/push code (licences first)
- [x] Write `protocol/` schema v1

## Phase 1 — text chat end to end

Gateway:
- [x] `app` config block, default off, explicit loopback port, static root
- [x] Listener: static files, WebSocket stream, bounded client frames and previews, fixed errors
- [x] `app pair` command, hashed device tokens, revoke by label
- [x] `src/channels/app.ts`: ingress, outbox egress, per-device cursor and ack
- [x] Events: `message`, `preview`, `status`, `settled`
- [x] Regression tests with a synthetic client and controlled clock
- [ ] Supervised deployment and installed-PWA pairing, streaming, and replay check
      (gateway config: `app.agentName: "Cody"`)

App:
- [x] Vite project, protocol types, manifest, icons
- [x] Connection with reconnect, cursor replay, idempotent send
- [x] IndexedDB store; chat renders from the store
- [x] First-run screen: install hint, pairing code entry
- [x] Chat screen: streaming markdown, composer, status pill

Done when: a message typed in the installed app gets a streamed answer, and
killing the app mid-answer loses nothing on reopen.

## Phase 2 — notifications

- [x] Gateway: VAPID key command, subscription endpoint, `web-push` sender,
      send-when-offline rule, drop on 404/410
- [x] App: permission prompt from a button, push handler, deep link, badge
- [x] Cron and worker results trigger a wake-up (scheduled deliveries append a message, which pushes)
- [x] Chunk oversized final answers losslessly across gateway and app

Done when: a scheduled reminder reaches a locked phone.

## Phase 3 — files

- [x] Gateway: upload endpoint, `media/app/` storage, download endpoint
- [x] App: attach from Photos, Files and camera; render files and images

## Phase 4 — agent surface

- [ ] Events: `activity` (done), `card` (later); tasks are a request, not an event
- [x] Three-level activity disclosure
- [x] Tasks tab: workers and cron jobs, cancel by id
- [x] Owner controls as UI: model picker, status sheet, new context
- [x] `ask_user` and quick-reply cards
- [x] MCP login owner surface
- [x] Side threads in the PWA (protocol v2, mock gateway)
- [x] Side threads in the gateway (fork exception under review)
- [x] Artifacts: agent-made HTML/SVG explainers (Mermaid later), rendered in a
      sandboxed iframe (`sandbox="allow-scripts"`, no same-origin, strict CSP,
      no network) so agent HTML can never reach `/v1` or the cookie; inline
      preview card in the chat, full-screen view, share/export
- [ ] Buttons and quick replies on agent messages (`card` actions, answered once) — `ask_user` cards cover the answered-once case; free-form buttons later
- [x] Reactions on messages: owner → agent as passive context (agent → owner later)

## Phase 5 — polish

- [x] Avatar states driven by `status` (six expressive robot avatar poses)
- [x] Desktop layout
- [x] Shortcuts: an authenticated "ask" endpoint for iOS Shortcuts
- [x] Voice (audio to the gateway's transcription path)
- [ ] Morning brief as a cron job with its own notification category
