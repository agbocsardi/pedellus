# Wire protocol v2

Normative contract between the PWA (this repository) and the gateway's `app`
channel (`durable-nanobot`). TypeScript shapes are in [v2.ts](./v2.ts); this
file wins where they disagree. Phase 1 implements everything not marked
_(later)_.

v2 = v1 plus **threads**: one main thread and owner-created side threads.
Everything else in v1 is unchanged. App and gateway ship v2 together; the
gateway accepts only `v: 2` (single owner, no mixed fleet).

## Threads

- `main` always exists, cannot be renamed or archived, and is the default
  wherever a `thread` field is omitted.
- Side threads have gateway-assigned ids `t_` + 1–40 chars `[A-Za-z0-9_-]`, a
  title of 1–80 printable characters, and are separate gateway chats (own
  context, own `/new`, turns may run in parallel). A thread created without
  `from` starts empty. A thread created with `from` is a fork of that thread's
  conversation at that message: it starts with exactly the context the source
  had up to and including it, and records it as `origin`. The inherited
  history is agent context only: it is not re-sent as events of the new
  thread (the app shows a "started from" card quoting the origin message from
  its own store instead). Only `user` and `assistant` messages can be fork
  points; a rejected fork replies `bad_request` and creates nothing.
- At most 50 non-archived side threads. Archived threads are read-only: `send`
  and `control` to them reply `bad_request`. Archiving is not deletion.
- Archiving is manual (`thread.archive`) or automatic: the gateway archives a
  side thread after a configured idle period (default 14 days without
  activity, never while a turn runs) with `archivedReason: "idle"`. A
  scheduled delivery into an archived thread restores it first.
- One event log and one cursor per device across all threads; every
  thread-scoped event names its `thread`.

## Transport

- Same origin for app and API, served behind `tailscale serve` (HTTPS).
- Authentication is the `durable_device` cookie (`HttpOnly; Secure;
  SameSite=Strict; Path=/v1; Max-Age=34560000`), set by `POST /v1/pair`. The
  400-day `Max-Age` matters: iOS drops session cookies when a home-screen app
  is closed, which would force re-pairing. Revocation is server-side. Nothing else
  authenticates; Tailscale identity headers are ignored.
- All JSON is UTF-8. Every size limit below is enforced by the gateway; the app
  enforces the same limits before sending.

| Limit | Value |
|---|---|
| WebSocket frame (either direction) | 262 144 bytes |
| `send.text` | 16 000 characters |
| `send.key` / request `id` | 1–64 characters `[A-Za-z0-9_-]` |
| Pairing code | 8 characters, `[A-Z2-9]` minus `I`, `O` (case-insensitive input) |
| Device label | 1–40 characters, printable |
| `hello.agent` | 1–40 printable characters |
| `control.args` | 1 000 characters |
| Archived threads in a `threads` reply | 200, newest activity first |
| Replay batch per `hello` | 500 events (client re-`hello`s with the new cursor for more) |

These bounds are `LIMITS` in [v2.ts](./v2.ts), which the gateway imports
rather than restating; `Pairing code` there also carries the alphabet.

## Pairing — `POST /v1/pair`

Request `{"code": "ABCD2345", "label": "iPhone"}`. The code comes from
`durable-nanobot app pair` on the host, is single-use and expires after 10
minutes.

- `204` with `Set-Cookie: durable_device=<token>; …` on success.
- `400 {"error":"bad_request"}`, `401 {"error":"invalid_code"}`,
  `429 {"error":"rate_limited"}` (more than 5 failures per minute across all
  clients). No other information in errors.

## Stream — `GET /v1/stream` (WebSocket)

The gateway always completes the upgrade, then closes with a 44xx code when the
cookie is missing, unknown or revoked, so the browser can tell auth failure from
a network failure.

| Close code | Meaning | App reaction |
|---|---|---|
| 4401 | Not paired / revoked | Drop to the pairing screen |
| 4400 | Protocol violation (bad JSON, unknown op, oversize frame) | Reconnect with backoff, log |
| 4426 | Unsupported protocol version | Show "update the app" (reload) |
| 4409 | Same device opened a newer stream | Do not reconnect while hidden |
| 1001/1006/other | Network or restart | Reconnect with backoff (1 s → 30 s, jitter) |

### Frames

Client → gateway, every request:

```json
{"type":"req","id":"r1","op":"<op>", ...fields}
```

Gateway → client, exactly one reply per request:

```json
{"type":"res","id":"r1","ok":true, ...result}
{"type":"res","id":"r1","ok":false,"error":"<code>"}
```

Error codes are fixed: `bad_request`, `too_large`, `unsupported`, `not_ready`,
`internal`. No free text.

Gateway → client, events:

```json
{"type":"event","event":"<name>", ...fields}
```

### Requests

| op | Fields | Result | Notes |
|---|---|---|---|
| `hello` | `v: 2`, `cursor: number \| null` | `v`, `device` (label), `head` (newest durable cursor), `agent` (display name, 1–40 chars, from gateway config `app.agentName`, default "Durable"), `commands: CommandInfo[]` (the slash commands this gateway offers on the app surface, in menu order), `presets: PresetInfo[]` (selectable model presets, config order; empty when the gateway has none) | Must be the first request; anything else first → close 4400. A later `hello` on the same stream is allowed and replays again from its `cursor` (how the app fetches the next batch). Wrong `v` → close 4426. After the reply the gateway replays durable events with `cursor > hello.cursor` (oldest first, at most 500), then the current `status` of `main` and of every thread whose state is not `idle`, then live events. |
| `send` | `key`, `text`, `thread?`, `attachments?: string[]` _(later)_ | `duplicate: boolean` | Idempotent by `key` for at least 7 days: a repeated key returns `ok` with `duplicate: true` and admits nothing. `ok` means durably admitted. |
| `ack` | `cursor` | — | Highest durable cursor the app has stored. Never decreases; a lower value is ignored. Drives retention and "offline" push decisions. |
| `control` | `command` (a name from `hello.commands`), `args?` (≤ 1 000 chars, the text after the name), `thread?` | — | Acts on that thread only. A name the gateway did not list → `unsupported`; bad arguments are answered by a usage `notice`. The visible result arrives as a `message` with `role: "notice"` in that thread. `CommandInfo` = `name` (`[a-z][a-z0-9_-]{0,22}`), `args?` (placeholder, e.g. `"[preset]"`), `summary` (one line), `usage` (the `Usage: /name …` line). The gateway's shared command catalogue is the source; the app never hardcodes the list. |
| `threads` | `query?` | `threads: ThreadInfo[]` | Without `query`: `main`, every open thread, and the 200 most recently active archived ones (keeps the reply inside the frame budget), newest activity first. With `query` (1–80 chars): every thread, archived included, whose title contains it case-insensitively, newest activity first, at most 200. `ThreadInfo` = `id`, `title`, `archived`, `archivedReason?: "manual" \| "idle"`, `origin?: {thread, messageId}`, `createdAt`, `lastAt` (ISO 8601). The app also keeps this list current from `thread` events. |
| `thread.create` | `key`, `title?`, `from?: {thread, messageId}` | `thread` (new id), `duplicate` | Idempotent by `key` like `send`. Missing title → gateway uses "New thread". Over the limit, or `from` naming an unknown thread/message or a message without a committed transcript entry → `bad_request`. With `from`, forks at that message. |
| `thread.rename` | `thread`, `title` | — | Not `main`. |
| `thread.archive` | `thread`, `archived: boolean` | — | Not `main`. `false` restores. Aborts a running turn in that thread first. |
| `ping` | — | — | App sends every 25 s while visible; no reply within 10 s → app closes and reconnects. |
| `history` _(later)_ | | | |
| `tasks` _(later)_ | | | |

### Events

Non-durable events are replaced per thread: a `preview` or `status` only
replaces the previous one of the same thread.

Durable events carry `cursor`: a positive integer, strictly increasing per
device, never reused. Delivered at least once; the app de-duplicates by
`cursor`. Non-durable events have no `cursor` and are replaced by the next of
the same kind.

| event | Durable | Fields |
|---|---|---|
| `message` | yes | `cursor`, `thread`, `id` (stable string), `role: "user" \| "assistant" \| "notice"`, `text` (markdown for `assistant`, plain otherwise), `at` (ISO 8601), `key?` (the `send.key` this is, or answers) |
| `settled` | yes | `cursor`, `thread`, `key`, `outcome: "answered" \| "failed" \| "aborted"` — the owner message `key` is finished |
| `divider` | yes | `cursor`, `thread`, `at`, `reason: "new"` — a `/new` context boundary |
| `preview` | no | `thread`, `key`, `text` — full answer-so-far markdown for the running turn (not a delta). Cleared by the matching `message`/`settled`. |
| `status` | no | `thread`, `state: "idle" \| "queued" \| "thinking" \| "tool" \| "error"`, `label?` (short, e.g. tool name) |
| `model` | no | `thread`, `preset` (name of the thread's current preset, or `null` when it uses a model outside the presets) — sent for every thread after replay and whenever a thread's selection changes. Change it with `control {command: "model", args: <preset>}`. `PresetInfo` = `name`, `label?` (short display text), `model` (`provider/model` id), `thinking?`. |
| `thread` | yes | `cursor`, `thread` (`ThreadInfo` fields: `id`, `title`, `archived`, `createdAt`, `lastAt`) — created, renamed, archived or restored |
| `activity`, `card`, `task` _(later)_ | | |

Ordering for one turn: `message{role:"user",key}` (admission echo, so other
devices see it), `status`/`preview` while running, `message{role:"assistant",key}`,
`settled{key}`.

## Delivery state in the app

| State | Meaning |
|---|---|
| queued | In IndexedDB, not yet sent (offline or not connected) |
| sent | `send` written to the socket, no reply yet |
| admitted | `send` replied `ok` (or the user echo with that `key` arrived) |
| answered / failed / aborted | `settled` arrived |

On reconnect the app resends every queued/sent message with its original `key`.

## App navigation (non-normative)

No swipe navigation: edge swipes collide with browser back gestures in Safari
and installed web apps. The thread list opens from an explicit header control
as a sheet; the main thread is pinned on top. Unread state per thread is local
to the app (last viewed cursor per thread).

Archived ("settled") threads stay findable: the sheet has a search field that
matches thread titles through `threads {query}` and message text through the
app's local store. Message-text search covers what the device has cached.
Manual archive and restore live in the thread's menu. Side threads started
with `from` show a small link chip under their origin message in the source
thread; a side thread's header has an explicit "‹ Main" button.
