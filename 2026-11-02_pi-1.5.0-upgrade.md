# Pi stack 1.5.0 upgrade (2026-11-02)

The `@earendil-works` stack moves from the pinned 1.4.0 to 1.5.0: `chord`,
`pi-ai`, `pi-codemode`, `pi-durable` and `pi-mcp` together, plus TypeBox 1.3.27 as
a direct dependency. The trigger was a model, not a feature: `gpt-6.1-terra` exists
only in the 1.5.0 catalogs, and a preset naming it fails startup on 1.4.0 with
`Unknown model openai/gpt-6.1-terra`.

## What the upgrade actually changed here

1.5.0 is not a drop-in patch. The port follows its own changelog; every decision
below is a translation of a documented break, not a local preference.

- **Tool schemas.** `pi-ai` no longer re-exports TypeBox at runtime, and its
  `index.d.ts` still names `typebox` without depending on it. `typebox` 1.3.27 is
  now a direct dependency and every `Type` import names it directly: nine tool
  modules in `src/` and two crash fixtures in `tests/fixtures/`. Tool arguments
  keep their TypeBox static types because `pi-schema`'s `Static` understands
  TypeBox schemas (`~kind`/`~unsafe`).
- **Commit subscription.** `Harness.subscribeCommits(listener)` is
  `Harness.observeCommits({ advance, end })`, returning `{ detach() }`. The episode
  indexer uses it for `pi.reset` entries and detaches on close.
- **Watches.** A watch listener receives Chord's tagged call, so a conversation
  view listener checks `call.kind === "value"`. `Conversation.viewState()` is gone;
  the terminal status adapter reads the same view from a short-lived
  `conversation.watch()`.
- **Submissions.** `SubmissionRecord` gained a `continue` variant. The terminal
  settlement type carries it through instead of silently relabelling it.
- **Parked work.** 1.5.0 removed `Harness.retryTask()`, the `restart_limit`
  blocked reason, `task_parked`, and the `retryable` hint that only existed to
  promise that retry. A restart-limited task now ends visibly (a faulted task, a
  tool's `restart_limit` error result, `pi.live.runFailure`, or a
  `task_interrupted` report). Consequences here:
  - `background-status` keeps `parked` for a task no installed definition can take
    and drops `retryable`, so `/status` promises no retry it cannot perform.
  - cron reports a blocked occurrence as `parked` regardless of reason.
  - the memory digest no longer calls a native retry before reporting busy: its own
    settlement frees the frontier.
  - episode-summary and cron docs no longer tell a host to call `retryTask`.
- **Recovery evidence.** This is the one product-semantics change worth reading
  carefully. `pi.live`'s attempt marker is now stored like streamed progress
  (`PROGRESS_COMMIT`), so a crash can lose the marker and the document with it. A
  missing marker therefore no longer proves that a pinned request was never
  dispatched: `preparedResponseEvidence()` reports `unrecorded` instead of the
  removed `not-dispatched`, and `listPreparedContextBlocks` never claims a proof it
  does not have. A cancellation is slightly more conservative about what it claims,
  not about what it refuses to replay.

## Verification

- `npm run typecheck` and `npm run build` are clean.
- `npm run test:behavior` (45 files) passes, with these test-side migrations:
  commit subscriptions, `viewState` → `watch`, TypeBox imports, the digest's
  removed native retry, and the recovery evidence value above.
- `test/terminal-cli.test.mjs`, `npm run test:execution` and
  `npm run test:core-acceptance` cover the terminal and execution surfaces.

## Residue

- The upgrade is only justified because a preset wanted `gpt-6.1-terra`; it was
  carried by the owner, not by a maintenance schedule. The next Pi release should
  be judged on its own changelog rather than assumed to be a patch bump.
- `typebox` is ours now, not a transitive gift. A future Pi AI that drops TypeBox
  compatibility would need a real migration to `pi-schema`'s `obj`/`str` builders.
- Dated plan notes from before this upgrade (`2026-10-*.md`) still describe
  `retryTask`, parks and `not-dispatched` as current behaviour. They are history and
  were not rewritten.
